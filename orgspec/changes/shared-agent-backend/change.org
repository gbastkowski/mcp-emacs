#+title: #+TITLE: shared-agent-backend

* Intent
Extract a shared agent-backend layer so Claude and opencode are
interchangeable backends behind one Emacs conversation UI, instead of
two parallel clients (issue #41).
Both backends now exist as non-terminal clients -- claude-client.el
(headless Claude, NDJSON over a subprocess) and opencode-client.el
(HTTP + SSE to opencode serve) -- which was the stated prerequisite
for this change. opencode gains, by construction, the first-class
features the Claude stack already has (project awareness, resume,
popup output, org transcript, human notes) by implementing the shared
interface, and Claude's richer surface becomes optional methods with
no-op defaults instead of required behaviour.

* Scope
This change covers the shared core (elisp/agent-backend.el), the
opencode port onto it (milestone 1), and the Claude port with its
event-subscriber migration (milestone 2).
Explicitly deferred to a later change: unifying the conversation
renderer, converging #39's mid-turn interruption rule, and moving the
window-placement defcustoms into the shared core.

* Approach
The seam is cl-generic methods on an EIEIO base class
`agent-backend' -- the Emacs-idiomatic polymorphism (project.el,
flymake, eglot). It gives :around/:after methods for cross-cutting
concerns (event publishing, history seeding) and lets a third backend
subclass without editing a central registry.

The load-bearing contract is the shared event vocabulary: every
backend translates its native stream events into :kind plists and
publishes them on one abnormal hook `agent-backend-event-functions'
(run with (BUFFER EVENT)), which replaces claude-client-event-
functions. The internal conversation models stay backend-internal --
Claude keeps its append-only event log, opencode keeps its part-based
message tables -- because forcing one model leaks transport details.

Mid-turn human input is `agent-backend-add-note' plus a backend
property `agent-backend-note-policy' (:interrupt / :steer / :queue).
The note is logged immediately; delivery is the backend's native
semantics. opencode's notes ARE steering prompts (delivery: steer);
Claude keeps its queue/interrupt/backpressure machinery. #39's "one
true interruption rule" is deliberately NOT settled here -- the change
standardizes the vocabulary, not the rule.

Backend-specific and staying out of the interface: transport,
session-store format, tool provisioning, the Claude-only IDE diff
review (mcp-emacs-ide.el), the Claude-only headless query, the
permission/question reply transports (opencode-only, no-op defaults
in the interface), and the renderer this milestone.

Phasing is opencode-first on purpose: the interface is designed from
the simpler 553-line backend so Claude's assumptions cannot leak in
(the issue's stated fear). Milestone 1 ports opencode and leaves
Claude untouched; milestone 2 ports Claude and migrates its event
subscribers (reshow-after-review, the remote org transcript) to the
shared hook.

* Delta

** The agent-backend class defines the conversation lifecycle interface :ADDED:
:PROPERTIES:
:AREA: agent-backend
:END:

The agent-backend module MUST define an EIEIO base class with
cl-defgeneric methods for connect, quit, send, interrupt, add-note,
note-policy, reply-permission, reply-question, list-sessions, resume,
seed-history, project-root, and render, and MUST provide no-op or
user-error default implementations for the optional capabilities
(permission/question replies, history seeding, resume, sessions) so a
backend that lacks them needs no stubs.

*** A minimal backend compiles against the defaults
GIVEN a backend subclass implementing only connect, send, interrupt,
add-note, note-policy, and quit
WHEN the module is byte-compiled
THEN the subclass is valid without further stubs

*** Resume is optional
GIVEN a backend without a session store
WHEN agent-backend-resume is called
THEN a user-error explains that the backend cannot resume

*** Replies are optional
GIVEN a backend that never asks for permission
WHEN agent-backend-reply-permission is called
THEN the default implementation is a no-op

** A shared event hook carries the backend-agnostic vocabulary :ADDED:
:PROPERTIES:
:AREA: agent-backend
:END:

The agent-backend module MUST publish every conversation event as a
plist with a :kind symbol on the abnormal hook
agent-backend-event-functions, run with (BUFFER EVENT), and the :kind
vocabulary MUST cover at least started, prompt, text, tool-use,
tool-result, finished, interrupted, note, notes-delivered,
note-dropped, resumed, permission-request, question-request, and
error. Subscribers MUST ignore unknown kinds.

*** Text events reach subscribers
GIVEN a backend publishes an assistant text event
WHEN a subscriber is registered on agent-backend-event-functions
THEN it is called with (BUFFER (:kind text ...))

*** Unknown kinds degrade to silence
GIVEN a subscriber that knows only :text
WHEN an event with an unknown :kind is published
THEN the subscriber runs without error

** A shared conversation mode holds the instance and common keys :ADDED:
:PROPERTIES:
:AREA: agent-backend
:END:

agent-backend-mode MUST derive from special-mode, MUST hold the backend
instance in a buffer-local variable, and MUST bind the common actions
(send, interrupt, add-note, quit, resume) in a shared keymap that
derived backend modes extend.

*** The instance is visible to subscribers
GIVEN a buffer in a derived backend mode
WHEN a subscriber reads the buffer-local instance
THEN it is the backend object of that conversation

*** The common keys are bound
GIVEN a derived backend mode
WHEN the shared keymap is inspected
THEN send, interrupt, add-note, quit, and resume are bound

** opencode-client implements agent-backend and publishes shared events :ADDED:
:PROPERTIES:
:AREA: opencode-client
:END:

The opencode client MUST define an agent-backend subclass, MUST
translate its SSE stream events into the shared :kind vocabulary and
publish them on agent-backend-event-functions, MUST derive its major
mode from agent-backend-mode, and MUST keep its public
opencode-client-* commands as thin wrappers over the generic methods.

*** SSE text maps to :text
GIVEN opencode streams an assistant text part
WHEN the frame is applied
THEN a :text event is published on the shared hook

*** Public commands stay stable
GIVEN the refactored client
WHEN opencode-client-send-prompt is called
THEN it dispatches through agent-backend-send and behaves as before

** opencode mid-turn input and replies use the shared primitives :ADDED:
:PROPERTIES:
:AREA: opencode-client
:END:

The opencode backend MUST implement agent-backend-add-note as a
steering prompt (delivery: steer; note-policy :steer), and MUST
implement reply-permission and reply-question against the opencode
HTTP endpoints.

*** A note steers the turn
GIVEN a turn is active
WHEN agent-backend-add-note is called
THEN a steer prompt is delivered and a :note event is published

*** Permission is answered
GIVEN opencode requests permission
WHEN agent-backend-reply-permission is called
THEN the permission reply endpoint is used

*** Questions are answered
GIVEN opencode asks a question
WHEN agent-backend-reply-question is called
THEN the question reply endpoint is used

** opencode exposes sessions through the shared surface :ADDED:
:PROPERTIES:
:AREA: opencode-client
:END:

The opencode backend MUST implement list-sessions from the opencode
session API, MUST make resume either reuse switch-session or signal
user-error, and MUST report no project scoping when it has none.

*** Sessions are listed
GIVEN opencode serve has sessions
WHEN agent-backend-list-sessions is called
THEN they are returned as (:id :label :time) plists

*** Resume without a picker fails clearly
GIVEN no native resume picker
WHEN agent-backend-resume is called
THEN a user-error names the alternative (switch-session)

** claude-client implements agent-backend and keeps its capabilities :ADDED:
:PROPERTIES:
:AREA: claude-client
:END:

The Claude backend MUST define an agent-backend subclass, MUST
translate its stream-json events into the shared :kind vocabulary
(the union minus permission/question, which it never emits), MUST
publish on agent-backend-event-functions, MUST derive its mode from
agent-backend-mode, and MUST keep its native notes (note-policy
:interrupt or :queue), resume, headless query, and IDE diff review
working as Claude-specific commands.

*** Stream-json maps onto the vocabulary
GIVEN a Claude stream-json message
WHEN it is handled
THEN it yields :text, :tool-use, :tool-result, or :finished events

*** Notes keep the Claude machinery
GIVEN note-interrupts is enabled
WHEN a human note arrives mid-turn
THEN the turn is interrupted and the note re-sent (note-policy
:interrupt)

*** IDE review stays Claude-only
GIVEN the IDE surface is enabled
WHEN Claude issues a native edit
THEN the ediff review still gates it

** Claude event subscribers migrate to the shared hook :ADDED:
:PROPERTIES:
:AREA: claude-client
:END:

claude-client-event-functions MUST be replaced by
agent-backend-event-functions, and its subscribers (the
reshow-after-review and the remote org transcript) MUST move to the
shared hook, so the existing Claude test suite passes unchanged.

*** Reshow runs from the shared hook
GIVEN a diff review ends
WHEN the window was captured
THEN the reshow-after-review subscriber fires from the shared hook

*** The Claude suite stays green
GIVEN the subscriber migration
WHEN the existing claude-client tests run
THEN they pass without modification

** The org transcript becomes a backend-agnostic subscriber :ADDED:
:PROPERTIES:
:AREA: remote
:END:

mcp-emacs-remote MUST subscribe to agent-backend-event-functions for
its runner transcript so it records opencode sessions as well as
Claude sessions, while its IDE-surface advice taps MUST remain
Claude-only.

*** opencode sessions are transcribed
GIVEN an opencode session with tool activity
WHEN the remote surface is enabled
THEN a per-project org transcript records it

*** IDE taps stay Claude-only
GIVEN the IDE surface
WHEN advice taps on IDE functions fire
THEN they still only apply to Claude
