#+TITLE: issue-108
#+PROPERTY: TRACKER
#+PROPERTY: ISSUE

* Intent
The interactive report commands (bug report, feature request) open a
composition buffer through ~agent-prompt-read~, which seeds a plain-text
template (~What happened:~, ~What you want:~, ...) and lets the human write
one long report. The filed GitHub issue body is that text as-is.

Gunnar asked for the composition buffer to open in a *markup major mode*
so the helpers (headings, emphasis, code blocks) are available while
writing, and settled on org-mode: it is built into Emacs, so there is no
new package dependency, and it fits the repo's org-native character. The
catch is that a GitHub issue body is rendered as markdown, not org, so the
composed text must be exported to markdown before filing. org ships the
~ox-md~ backend, so the conversion is available without extra machinery.

This change makes the report composition buffer start in org-mode and
exports the composed body to markdown (via ~ox-md~) at filing time, so the
human writes in org and the issue renders as markdown.

* Scope
In scope:
- The two interactive report composition buffers (~mcp-emacs-report-bug~ /
  ~mcp-emacs-report-feature~) open in org-mode instead of the generic
  markdown/text choice.
- The per-kind body templates become org headings (~* What happened~ etc.)
  so they render as headings in the filed issue.
- The body is exported org-to-markdown immediately before filing, using
  ~ox-md~ (bundled with org; no new dependency).
- Empty template headings are still stripped before filing, now also when
  they are org headlines.
- Recovery keeps the raw composed text the human actually wrote.

Out of scope:
- The general agent-prompt composition buffer (prompts) keeps its current
  markdown-if-available / text default -- this only changes the report
  buffers.
- The non-interactive ~mcp-emacs-report-tooling-issue~ core is untouched:
  a caller-supplied body is passed through as-is, not org-converted.

* Approach
- 1. Drive org-mode from the report composer only: ~mcp-emacs-report--compose~
  binds ~agent-prompt-major-mode~ to ~org-mode~ for the ~agent-prompt-read~
  call, keeping the send/abort bindings (~agent-prompt-mode~ minor mode)
  on top of org-mode. General prompts are unaffected (their default stays).
- 2. Make the templates org headings: the per-kind scaffolds in
  ~mcp-emacs-report--templates~ become org headlines (~* What happened~,
  ~* What you expected~, ~* How to reproduce~, ~* What you want~, ~* Why it
  would help~), so writing a report looks like org and exporting renders
  headings.
- 3. Reuse the empty-heading stripping for org headlines:
  ~mcp-emacs-report--heading-p~ also recognises an org headline with nothing
  after it, so an unanswered ~* How to reproduce~ is still dropped before
  filing.
- 4. Export to markdown on filing: ~mcp-emacs-report--org-to-md~ exports a
  body through ~ox-md~ (~org-export-as 'md~) when org is available, falling
  back to the original text otherwise. ~mcp-emacs-report--file-composed~
  converts the body (never the title) right before filing, so the issue
  body is markdown while ~mcp-emacs-report-last-text~ still holds the raw
  org the human typed, for recovery unchanged.
