#+TITLE: remove-the-prompting-questions-in-the-feature-request-buffer
#+PROPERTY: TRACKER github
#+PROPERTY: ISSUE gbastkowski/mcp-emacs#107

* Intent
The feature-request composition buffer opens pre-seeded with prompting
headings — "What you want:" / "Why it would help:" — because a note written
in thirty seconds should still say enough to act on.  Gunnar finds the
scaffold more noise than help for a feature idea and asked to drop it: a
feature request should open as an empty text buffer (or with the active
region seeded), the same as `mcp-emacs-report-template' being nil.  The bug
report keeps its scaffold, which is the case where the prompts carry real
weight ("How to reproduce:" is the part a bug report is useless without).

* Scope
In scope:
- The feature request no longer seeds prompting headings by default: the
  `feature' entry drops out of `mcp-emacs-report--templates'.
- The bug report keeps its scaffold unchanged.
- The existing escape hatches stay intact: `mcp-emacs-report-template' nil
  still opens an empty buffer for every kind, and a region in the source
  buffer still seeds the composed report.
- Tests updated to pin the new default.

Out of scope:
- A templating engine (yasnippet or otherwise) to offer optional feature
  templates.  Gunnar floated this as a question on the issue ("WDYT?"); it
  is a larger, separate decision and is tracked as a follow-up, not
  guessed into this change.

* Approach
- Remove the `("feature" . "...")` entry from
  `mcp-emacs-report--templates` and update its docstring: templates now
  cover only kinds that benefit from scaffolding, and `feature' receives
  none.
- `mcp-emacs-report--initial` needs no change — it already seeds whatever
  `mcp-emacs-report--templates` has for the kind, so a missing `feature'
  entry means an empty buffer (modulo a source region), exactly the
  requested default.
- Update the report test suite: the "offers the feature template" case now
  asserts no feature scaffold by default, while the bug-scaffold case stays.
