* Intent
The project has grown past the README's quickstart, and Gunnar wants a
guided intro like `vimtutor`/Emacs tutor for a newcomer — human, not agent.
A short 10-minute introduction is the agreed first cut (to be extended
later). It should be a side window showing precise instructions the user
reads and follows; advancing/scrolling is manual, so no keybinding-driven
lesson player is needed in this slice.

The tutor is documentation with a thin container: a command opens a
read-only side window of Org text that walks the user through the
headline flow (start the server → point a client at it → run an agent
client → see an edit gated by `apply_diff`), one section per step. No new
dependencies, no network, no interaction model beyond read-and-do.

* Scope
In scope:
- A command that opens the tutor as a side window of static, read-only
  text (Org), ~10 minutes of reading.
- ~8–10 short steps covering the project's headline surfaces: start the
  MCP server, attach a client, run an agent client inside Emacs, and see a
  native edit gated behind diff review.
- Manual scrolling/advancing; a step is a section, not a state machine.
- Written for humans learning the Emacs-side UX.

Out of scope:
- A keybinding/state-machine lesson player (advancing is manual).
- Agent-facing (MCP-tool-surface) documentation.
- Auto-open on first run.
- Any new runtime dependency or network access.

* Approach
- Add `elisp/mcp-emacs-tutor.el` with a `mcp-emacs-tutor` interactive
  command. It renders a docstring-style Org buffer into the middle-right
  side window using the ordinary `display-buffer-in-side-window`
  mechanism, read-only.
- The lesson text lives in the same file as an Org string (one headline
  per step), explicit in the code so it is versionable and diffable like
  the specs it teaches.
- README gets a one-line pointer to `M-x mcp-emacs-tutor` under "Pick your
  entry point".
- Tests: `mcp-emacs-tutor-test.el` asserts the command produces a
  non-empty read-only side buffer whose content contains the step
  headlines, and that repeated invocation reuses the same buffer.
